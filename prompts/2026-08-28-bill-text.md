## Why this lane exists

We hold 2.2 million bills across 52 jurisdictions — titles, descriptions, sponsors, history, votes — and **not one bill's text**. `"Documents"` (2.3M rows) holds *links*: LegiScan's `url` and the legislature's own `state_link`, with `document_type` (text / amendment / supplement), `document_mime`, `document_size`, `document_desc` ("Introduced", "Enrolled", "Chaptered"…). Search on titles is a card catalogue; search on text is the library. **Deliverable: the text of every bill we can get for free, in Neon, joined to `"Bills"` by `bill_id`, with a nightly job that keeps it current — starting with New York and Congress complete, then every state's current and prior session.**

The budget that shapes everything: LegiScan's `getBillText` is one API query per document, and the key allows 30,000 a month. 2.3M documents is 80 months. So LegiScan text is for the **nightly delta only**; the corpus comes from the legislatures themselves, which publish it free and without a cap.

## Sources, in priority order

1. **New York — the NY Senate Open Legislation API** (`https://legislation.nysenate.gov/api/3/`, key `NYS_LEGISLATION_API_KEY`, already on the box). `GET /bills/{sessionYear}/{printNo}` returns every amendment version's `fullText` (plain text; the `view=only_fulltext` / `with_refs` views exist — pick the cheapest that carries the text and say which). Our NY rows carry `bill_number` = print number and `session_id` = session year, 2009 →. ~188k bills; a `fullText` response is 20–500 KB. Politeness: no published hard limit, so **≤ 5 requests/s, one at a time, back off on 429/5xx**. Note for the record: "LBDC" is the **Legislative Bill Drafting Commission**, the NY body whose data feeds Open Legislation is built on; its feeds are by arrangement, not a public download — the API is the free route, and it is complete.
2. **Congress — govinfo bulk data**, no key: `https://www.govinfo.gov/bulkdata/BILLS/{congress}/{session}/{type}/` (types `hr s hjres sjres hconres sconres hres sres`), one XML per bill version, with per-directory zips (e.g. `…/hr/BILLS-119-1-hr.zip`). Bill number joins as `HB1234 ↔ hr1234`, `SB ↔ s`, `HJR ↔ hjres`, `SJR ↔ sjres`, `HCR ↔ hconres`, `SCR ↔ sconres`, `HR ↔ hres`, `SR ↔ sres`; congress = `(session_id − 1789) / 2 + 1` (2025 → 119, 2009 → 111). XML → text: strip tags, keep section structure as newlines. ~131k bills, 111th–119th; a few GB of XML, download the zips once.
3. **Everyone else, current + prior session (`session_id ≥ 2023`) — the `state_link` walker.** For each `"Documents"` row of `document_type = 'text'` (amendments too, if cheap) whose bill is in scope, fetch `state_link` **on the legislature's own site**, convert to text (`text/html` → strip; `application/pdf` → `pdftotext -layout` from poppler-utils, install it on the box; anything else → record the mime and skip), store. Rules, non-negotiable: **one connection per host, ≥ 1 s between requests to the same host, a `User-Agent` naming livingston and a contact address, honour `robots.txt` and `Retry-After`, give up on a host after 5 consecutive 403/429 and move on** — a state site that blocks us is a state we do later by another route, not a state we hammer. Skip documents over 20 MB. Census first (`--census`): per state, how many documents, how many bytes, how many hosts — and report it before fetching anything. Expect ~350k documents over 50 hosts and a few days of polite fetching; that is fine, it runs unattended.
4. **New Jersey, all history** (2010 →) — same walker, `state_link` on `pub.njleg.gov`; NJ publishes the HTM per bill version. Its bulk "Legislative Data" downloads carry actions and sponsors, not text, so the walker is the route.
5. **The nightly delta — LegiScan `getBillText`.** `api/legiscan-sync.ts mode=delta` already knows which bills changed today. For each changed bill's new `texts[]` entries: try `state_link` first (free), fall back to `getBillText(doc_id)` (base64; counts against the 30k/month — log the running monthly count and **stop at 25,000**). This is what keeps NY/US/everyone current after the backfill, and it covers every state, not just the ones the walker has reached.

Order of work: **1 and 2 first, in parallel** (both free, both complete, both easy); then 3 by state in the order of the census (biggest first, NJ included as 4); 5 is built alongside and switched on when 1 is done.

## Storage — `"BillTexts"`

One row per document version, text only (no PDFs in Neon — if we ever want the originals they go to S3, not here):

```
"BillTexts" (
  document_id bigint PRIMARY KEY,        -- LegiScan doc id; for NY/US rows without one, a negative synthetic id from a sequence, and say so
  bill_id bigint NOT NULL, state text NOT NULL, session_id int, version text,   -- "Introduced", "Amended A", "Enrolled"…
  source text NOT NULL,                  -- 'nysenate' | 'govinfo' | 'state_link' | 'legiscan'
  mime text, chars int, text text, text_hash text, fetched_at timestamptz NOT NULL, error text)
INDEX (bill_id), INDEX (state, session_id)
```
Plus `Bills.text_fetched_at` and `Bills.text_chars` (the latest version's) so the UI can show "text available" without a join, and so the nightly delta knows what it owes. **Add `search_tsv tsvector GENERATED ALWAYS AS (to_tsvector('english', left(text, 1000000))) STORED` with a GIN index** — that is the search lane's raw material and it is far cheaper to create now than to backfill later; measure its size in the report. Idempotent DDL in a `prepareSchema` like the other handlers. No `DELETE`, no `DROP`.

## Code, in the repo

- `api/bill-text.ts` — the handler (same shape as the others: `CRON_SECRET`, `(req, res)`, runnable through `scripts/box/run-handler.mjs`): `?source=nysenate|govinfo|state_link|legiscan`, `?state=`, `?session=`, `?limit=`, `?census=1`, `mode=delta`. Idempotent: a row whose `text_hash` is unchanged is not rewritten.
- `scripts/box/text-backfill.mjs --source … --state … --since-session 2023` — the DB-resumable driver (resumes from `"BillTexts"` / `Bills.text_fetched_at`, never from a log), politeness built into the fetcher not the driver, checkpoint = every row is its own commit.
- `ops/box/jobs.d/lv-text-delta.json` — nightly, `"repo": "livingston"`, after `lv-legiscan-delta` by filename order; steps `run-handler api/bill-text.ts mode=delta`. House-style `_why`.
- Backfills run under `run-job` with their own names (`lv-text-ny`, `lv-text-us`, `lv-text-walk`), `--heap 2048`, one at a time per host, at most two jobs concurrently on the box (`MAX_CONCURRENT=2` is the scheduler's rule; honour it for hand-started jobs too and check `tmux ls` first — LDA and FEC may still be running).
